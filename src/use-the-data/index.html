Use the data

Simulation: the billboard on this site does not exist. The Algarve weather on it is real, and so is the weather for Porto, Braga and Lisbon. It comes from public JSON files that anyone can read, with no key. This page shows where they are, why the screen reads each one, how to read them, the terms that come with them, and how to build a screen like this one.

What data.promptugal.news is

data.promptugal.news is the raw data behind the PrompTugal.news sites: public data about Portugal (weather, warnings, sea, UV, flights seen near Faro, events), collected by code on a schedule and served as plain JSON files. There are no articles and no model in the loop. Every file is a GET request with no key, and any website may read it from a visitor's browser (CORS is open).

  • llms.txt: the data site in one text file, for people and agents.
  • Catalogue (api/v1/index.json): every source with its title, publisher, cadence, read_at, status and addresses. Read addresses from here rather than building them by hand.
  • OpenAPI 3.1 (api/v1/openapi.json): every path with a schema and an example.
  • Contract (api/v1/README.md): the version 1 addresses and fields stay for the life of version 1; a breaking change goes to api/v2/.

Each source has three files in its own folder, https://data.promptugal.news/api/v1/<source>/:

  • latest.json: the records from the last read, with their provenance (read_at, the source address, the publisher's page and the terms).
  • reads.json: a log of the collector's runs, newest first: each request's address, HTTP status, size, the start of its checksum, and whether the bytes changed. It logs runs, not values.
  • card.json: who publishes the data, the terms, the schedule. Read the card before you reuse a value.

There is also one file per Algarve place, api/v1/by-place/now/<place>.json, that picks out the nearest IPMA values for that place, each with its own source and time read.

The files this screen reads, and why

The screen has two sides: "there" (a place in the Algarve) and "here" (where the screen stands). The Algarve side is always live. The here side is live for Porto, Braga and Lisbon, and simulated for London, because no London source exists on data.promptugal.news (checked 18 November 2026).

Copy and paste

Each example runs in a browser console or in Node 18 and later (JavaScript), or in a terminal with curl and jq. They only read: every request is a GET.

JavaScript

const base = 'https://data.promptugal.news/api/v1';
const get = async url => {
  const r = await fetch(url);
  if (!r.ok) throw new Error(`${url}: HTTP ${r.status}`);
  return r.json();
};

// 1. List the sources, with publisher, cadence, last read and status
const cat = await get(`${base}/index.json`);
for (const s of cat.sources)
  console.log(s.id, '|', s.publisher, '|', s.cadence, '|', s.read_at, '|', s.status);

// 2. Faro now: the nearest IPMA station's latest hour, and today's IPMA forecast
const faro = await get(`${base}/by-place/now/faro.json`);
const r = faro.station.reading;
console.log(`${faro.station.name}, ${faro.station.km} km: ${r.temp_c}°C, ${r.rain_mm} mm rain, hour ${r.at}`);
const today = new Date().toLocaleDateString('en-CA', { timeZone: 'Europe/Lisbon' });
console.log('Today:', faro.forecast.days.find(d => d.date === today));
console.log('Source: IPMA, via data.promptugal.news, read', faro.reads.observations.at);

// 3. The forecast for Porto, by IPMA id (Braga 1030300, Lisbon 1110600)
const fc = await get(`${base}/ipma-city-forecasts/latest.json`);
const porto = fc.cities.find(c => c.id === 1131200);
for (const d of porto.days)
  console.log(d.date, `${d.t_min_c} to ${d.t_max_c}°C`, `${d.rain_prob_pct}% rain`, `type ${d.weather_type}`);
console.log('Source: IPMA, read', porto.read_at);

// 4. The nearest IPMA station that reported a temperature this hour, to a point (Braga)
const obs = await get(`${base}/ipma-observations/latest.json`);
const km = (a, b, c, d) => {
  const p = Math.PI / 180;
  const h = Math.sin((c - a) * p / 2) ** 2 + Math.cos(a * p) * Math.cos(c * p) * Math.sin((d - b) * p / 2) ** 2;
  return 2 * 6371 * Math.asin(Math.sqrt(h));
};
const [lat, lon] = [41.5475, -8.4227];
const near = obs.stations
  .filter(s => s.reading && s.reading.temp_c !== null)
  .map(s => ({ ...s, km: km(lat, lon, s.lat, s.lon) }))
  .sort((x, y) => x.km - y.km)[0];
console.log(`${near.name}, ${near.km.toFixed(0)} km: ${near.reading.temp_c}°C at ${obs.hour_utc} (IPMA)`);

// 5. Read a card: who publishes the data, how often it is read, and the terms
const card = await get(`${base}/ipma-observations/card.json`);
console.log(card.publisher, '|', card.schedule.cadence, '|', card.terms.summary, '|', card.terms.page);

// 6. When did the collector last run, and did every request succeed?
const reads = await get(`${base}/ipma-observations/reads.json`);
const last = reads.runs[0];
console.log(`last run ${last.at} to ${last.finished}: ${last.ok} ok, ${last.failed} failed`);

// 7. Stale check: older than twice the card's cadence means say so, never guess
const staleAfterMin = cadence => {
  if (cadence === 'hourly') return 120;
  const m = /every (\d+) hours?/.exec(cadence || '');
  return m ? Number(m[1]) * 120 : 120;
};
const latest = await get(`${base}/ipma-city-forecasts/latest.json`);
const fcCard = await get(`${base}/ipma-city-forecasts/card.json`);
const ageMin = Math.round((Date.now() - Date.parse(latest.read_at)) / 60000);
console.log(ageMin > staleAfterMin(fcCard.schedule.cadence)
  ? `Stale: read ${ageMin} min ago. Say so; do not show it as now.`
  : `Fresh: read ${ageMin} min ago.`);

curl and jq

# 1. List the sources: id, cadence, last read, status
curl -s https://data.promptugal.news/api/v1/index.json \
  | jq -r '.sources[] | [.id, .cadence, .read_at, .status] | @tsv'

# 2. Faro now
curl -s https://data.promptugal.news/api/v1/by-place/now/faro.json \
  | jq '{station: .station.name, km: .station.km, hour: .station.reading.at,
         temp_c: .station.reading.temp_c, rain_mm: .station.reading.rain_mm,
         read_at: .reads.observations.at}'

# 3. The forecast for Porto, by IPMA id
curl -s https://data.promptugal.news/api/v1/ipma-city-forecasts/latest.json \
  | jq -c '.cities[] | select(.id == 1131200) | .days[] | {date, t_min_c, t_max_c, rain_prob_pct, weather_type}'

# 4. The nearest reporting station to a point (Braga; a flat approximation, close enough at these distances)
curl -s https://data.promptugal.news/api/v1/ipma-observations/latest.json \
  | jq -r --argjson lat 41.5475 --argjson lon -8.4227 '
      .hour_utc as $h
      | [.stations[] | select(.reading != null and .reading.temp_c != null)
         | . + {km: ((((.lat - $lat) * 111.2) | . * .)
                   + (((.lon - $lon) * 111.2 * ($lat * 3.14159265 / 180 | cos)) | . * .) | sqrt)}]
      | min_by(.km) | "\(.name), \(.km | round) km: \(.reading.temp_c) C at \($h) (IPMA)"'

# 5. Read a card and its terms
curl -s https://data.promptugal.news/api/v1/ipma-observations/card.json \
  | jq '{publisher, cadence: .schedule.cadence, terms: .terms.summary, page: .terms.page}'

# 6. When did the collector last run?
curl -s https://data.promptugal.news/api/v1/ipma-observations/reads.json \
  | jq '.runs[0] | {at, finished, ok, failed}'

# 7. Stale check (hourly source: stale after 120 minutes)
curl -s https://data.promptugal.news/api/v1/ipma-city-forecasts/latest.json \
  | jq -r '(now - (.read_at | fromdateiso8601)) / 60 | floor
           | if . > 120 then "stale: read \(.) min ago" else "fresh: read \(.) min ago" end'

Each example was run against the live files on 18 November 2026 at about 18:10 UTC and returned data. Then, for example 4, the nearest station to Braga's centre that had reported a temperature was 16 km away; the screen says which station it uses and how far it is, because Braga's own stations do not always report.

How to read a card and its terms

Every source has a card.json. These are the fields of the ipma-observations card, as read on 18 November 2026:

id, title, what
The source's name in the addresses, its title, and one sentence on what it holds ("The latest hourly observation of each IPMA surface station: temperature, humidity, wind, rain, pressure and radiation, with the station's name and position").
publisher
Who publishes the data: "IPMA, Instituto Português do Mar e da Atmosfera". Name them beside every figure you show.
source_home, reader_page
The publisher's own file that the collector reads, and the publisher's page for people. Link the reader page when you show a value.
schedule.cadence, schedule.how
How often the collector is meant to read the source ("hourly") and what runs it. Runs can be late; reads.json shows when they really happened.
terms
terms.summary in plain English; terms.quote in the publisher's own words, with terms.quote_lang ("pt"); terms.page, where the terms were read, and terms.read_at, when; terms.republish ("with conditions: attribution to IPMA; no profit-making purpose"); and terms.open_question, anything not yet settled.
license
The licence of the file's structure: CC BY 4.0, held by PrompTugal.news. The values inside keep their source's own terms, which come first.
api
The source's addresses: latest, reads, card, openapi and its page.
vault, split, cost, since
Where the raw bytes are kept, who did what (code, agents, people), what a run costs, and when the source started. The card says no person has checked the values yet.

read_at is not on the card: it is on latest.json (in provenance) and in the catalogue. It is the time the collector last read the source, in UTC. Show it with every figure.

The terms

  • IPMA (forecasts, observations, sea, UV, warnings): "free to copy and use for personal or public use if the use has no profit-making or offensive purpose; always name IPMA as the source." So: always name IPMA, beside the figure, and no profit-making use. This site has no ads, no payments and no profit-making purpose. A real campaign would be a profit-making use and would need IPMA's permission first.
  • adsb.lol (aircraft near Faro): its data is under the Open Database License (ODbL 1.0): attribution and share-alike, so anything derived from it stays under the ODbL. Coverage depends on volunteers' receivers, so an aircraft missing from the file may still have been there.
  • events-pt (the planning assistant's events): no reuse licence or terms page was found for any of its sources, so the card says reference use only, name the source, link to the event, and no AI training. The planning assistant shows only an event's name, date, venue and a link, and asks you to check with the organiser.
  • The files' structure: CC BY 4.0, PrompTugal.news. Every value keeps its source's terms.

Terms quoted from each source's terms.summary on its card, read 18 November 2026. IPMA's own terms page: api.ipma.pt.

Stale or missing data: what the screen does

  • Every value has a time. Beside each live figure the screen shows its source, publisher and the time it was read.
  • Stale means older than twice the card's cadence: two hours for the hourly IPMA and adsb.lol files, twelve hours for events-pt. That limit is this site's choice, not the publishers'. A stale value is not shown as now: the screen says how old it is.
  • Missing means say so. A file that does not answer within 8 seconds, answers with an error or holds no value is named on the page as unread. The screen never guesses a value and never fills a gap with a typical one.
  • No Algarve reading, no advert. If the Algarve file cannot be read, the screen says a real screen would pause now.
  • A failed run keeps the last good file. data.promptugal.news keeps a source's last good latest.json when a read fails, and reads.json shows the failure (runs[0].failed above 0). That is why the screen checks read_at rather than trusting that a file is new.

How to build a screen like this one

This is how this simulation is built, offered as a pattern, not as advice for a real campaign.

  1. 100% client side. The site is static files (HTML, CSS, JavaScript) on a static host. There is no server, no key and no database. State (the chosen place, city and London weather) lives in the address bar or the browser's local storage.
  2. Fetch in the browser. When the page opens, the browser reads the files above from data.promptugal.news, with a time limit, once per address per page load. Nothing is copied into the site at build time, so the figures are as fresh as the collector's last run.
  3. The three phases of Dinis Cruz's white paper, which the screen runs: first, the Algarve now, with a simple message; second, the weather compared with here for the next days, with an indicative flight time and price; third, how soon you could be there, with a QR code to a planning assistant. On this site the flight times and prices are invented examples, and the planning assistant is a simulation: scripted answers, no live model.
  4. Sun computation. Sunrise, sunset and the sun's height are computed in the browser from the date and each place's position, with the NOAA solar calculator's equations (after Jean Meeus, "Astronomical Algorithms"). No file is read for this. The screen uses it for the darker test in the decision rule below, and for day and night in the drawing.
  5. The decision rule. A real screen would run the advert when here is colder (by 3°C or more), wetter (raining here, dry there) or darker (the sun has set here and not yet there, or daylight ends at least 30 minutes earlier here) than the Algarve place. When the Algarve is wet too, it would switch message to the next drier day in IPMA's forecast (chance of rain under 40%), or pause if there is none. With no Algarve reading, it pauses. The screen says, in words, which of these it would do and why.
  6. London is simulated until a source exists. data.promptugal.news has no London weather (checked 18 November 2026). A control beside the screen sets London's weather, time and station, and every London figure is labelled "simulated". Porto, Braga and Lisbon are read live from IPMA and labelled "live".
  7. Cameras only through live.promptugal.news. The white paper's live view would come from public cameras. This site will show a camera only once live.promptugal.news offers one with its terms. On 18 November 2026 that site said "First version coming" and offered none, so the screen shows a drawing, marked "drawing, not a camera".
  8. Label everything. "live" for values read from a source, "simulated" for values the visitor sets, "invented example" for flights, prices and times, "drawing, not a camera" for the scene, and "simulation: scripted answers, no live model" for the planning assistant.

What a real screen would need first, and this site does not have: permission from IPMA for a profit-making use; a real London weather source; each camera operator's permission; a real flight and price source with its own terms; and a screen, a site for it and a buyer, none of which exist.

Not a warning service

Nothing on this site is a warning service or safety advice. For weather warnings and safety in Portugal, follow IPMA (ipma.pt) and ANEPC, the national civil protection authority.
